# نقل متجر Ehab Store إلى هذا المشروع

الخبر الجيد: المشروع المرفوع مبني على نفس التقنية المستخدمة هنا (TanStack Start + نفس قالب Lovable)، لذلك النقل يتم بنسخ مباشر دون إعادة كتابة أو تحويل للمسارات.

## ما يحتويه الأرشيف

- 224 ملفاً: 40+ صفحة/مسار (الرئيسية، المنتجات، السلة، الدفع، الحساب، المفضلة، الولاء، الطلبات، لوحة تحكم إدارية كاملة بـ 18 قسماً)
- مكونات واجهة كاملة (shadcn) ومكونات مخصصة (بطاقة منتج، تقييمات، خريطة مواقع، واتساب، بانرات إعلانية)
- منطق الأعمال في `src/lib` (طلبات، كوبونات، ولاء، عملات، توصيل، فواتير، نسخ احتياطي، صور AI)
- الصور والشعار في `src/assets`، وأيقونات PWA
- ملفات ترحيل قاعدة البيانات في `supabase/migrations`

## ما تحتويه النسخة الاحتياطية

نسخة PostgreSQL كاملة تضم 28 جدولاً في المخطط العام: المنتجات، التصنيفات، الماركات، خيارات المنتج، الأسعار، الطلبات وبنودها، الفواتير، الكوبونات، برنامج الولاء بكامل جداوله، العملات، مناطق التوصيل، طرق الدفع، التقييمات، الإعدادات، الثيمات، البانرات، الملفات الشخصية وأدوار المستخدمين — بالإضافة إلى حسابات المستخدمين في مخطط المصادقة.

## خطوات التنفيذ

1. **تفعيل Lovable Cloud** — إنشاء قاعدة البيانات والمصادقة والتخزين لهذا المشروع.
2. **نسخ الكود** — نقل `src/` بالكامل (المسارات، المكونات، المكتبات، الأصول) و`public/` وملفات الإعداد، مع استثناء بيانات Git وملف `.env` القديم.
3. **مطابقة الحزم** — تثبيت الاعتماديات الإضافية التي يحتاجها المشروع (Leaflet للخرائط، recharts للرسوم، vite-plugin-pwa، مكونات Radix الناقصة).
4. **إعادة توليد اتصال قاعدة البيانات** — استبدال ملفات `src/integrations/supabase` بالنسخة المولّدة لهذا المشروع الجديد، مع الحفاظ على وسيط المصادقة وحماية المسارات.
5. **استعادة قاعدة البيانات** — تحويل النسخة الاحتياطية إلى ملف ترحيل SQL يشمل الجداول والأنواع والدوال وسياسات الأمان والصلاحيات وبيانات الصفوف، ثم تطبيقه.
6. **استعادة حسابات المستخدمين** — نقل صفوف المصادقة مع الحفاظ على المعرفات حتى تبقى الطلبات والملفات الشخصية مرتبطة بأصحابها.
7. **إعادة إنشاء مساحات التخزين** — إنشاء نفس الحاويات وسياساتها.
8. **التحقق** — بناء المشروع وفتح الصفحات الرئيسية ولوحة التحكم للتأكد من ظهور البيانات الفعلية.

## أمور تحتاج انتباهك

- **ملفات التخزين**: النسخة الاحتياطية تحتوي على سجلات الملفات فقط، لا على الملفات نفسها. صور المنتجات المرفوعة سابقاً عبر لوحة التحكم ستحتاج إعادة رفع أو مزامنة لاحقة (صور `src/assets` غير متأثرة).
- **المفاتيح السرية**: أي مفاتيح خارجية في المشروع القديم (مثل مفاتيح الخرائط أو الإشعارات) يجب إدخالها عبر نافذة الأسرار الآمنة، وليس لصقها في المحادثة.
- **كلمات مرور المستخدمين**: تُنقل مشفّرة كما هي إن كانت ضمن النسخة، وإلا سيحتاج المستخدمون إعادة تعيين كلمة المرور.
- **روابط الخدمات الخارجية**: عناوين النطاق ستتغير، لذا أي خطاف (webhook) أو مهمة مجدولة تشير للمشروع القديم تحتاج تحديثاً.

## ملاحظة تقنية

المصدر يستخدم نفس إصدار القالب تقريباً (`tanstack_start_ts_current`)، لذا لا توجد ترقية إطار عمل مطلوبة. المسارات ملفية بنفس الاصطلاح، وملف `routeTree.gen.ts` يُعاد توليده تلقائياً. مسارات MCP و OAuth الموجودة في المصدر ستُنقل كما هي.
